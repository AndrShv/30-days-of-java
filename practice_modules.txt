1. Модуль «Idempotent Event Consumer» (Spring Boot + RabbitMQ/Kafka + Redis)
--------------------------------------------------------------------------------
Проблема: Сообщение из брокера может прийти дубликатом. Если это списание 
баланса или создание записи — система продублирует операцию.
Что пишем:
- Spring Boot приложение с кастомным @Idempotent аспектным декоратором (AOP).
- Проверка MessageId через Redis (операция SETNX с TTL).
- Если обработка упала — отправка сообщения в DLQ (Dead Letter Queue) 
  с правильной стратегией retries.


2. Модуль «Transactional Outbox Pattern» (Spring Boot + PostgreSQL + Kafka)
--------------------------------------------------------------------------------
Проблема: Если сохранить сущность в БД, а потом попытаться отправить событие 
в Kafka — брокер может быть недоступен. Если сделать наоборот — может упасть 
БД. Данные рассинхронизируются.
Что пишем:
- Сохранение записи и события в таблицу outbox_events в рамках одной единой 
  транзакции @Transactional.
- Фоновый воркер (@Scheduled или Scheduled Executor), который вычитывает 
  необработанные события из таблицы outbox_events и атомарно отправляет их в Kafka.


3. Модуль «Resilience & Rate Limiting Guard» (Spring Boot + Resilience4j + Redis)
--------------------------------------------------------------------------------
Проблема: Внешний сторонний API постоянно тормозит или падает, а наш сервис 
уходит в дедлок из-за зависших потоков.
Что пишем:
- Интеграция Resilience4j: паттерны Circuit Breaker (размыкатель цепи при частых 
  ошибках) и Retry с экспоненциальной задержкой.
- Реализация RateLimiter на Redis (ограничение 5 запросов в секунду на 
  пользователя).


4. Модуль «Integration Testing & Migrations» (Testcontainers + Liquibase + JUnit 5)
--------------------------------------------------------------------------------
Проблема: Использование H2 в тестах скрывает специфичные фичи PostgreSQL и 
некорректно работает с SQL-миграциями.
Что пишем:
- Настройка Liquibase скриптов (XML/SQL changelogs) для инициализации БД.
- Написание интеграционных тестов с помощью Testcontainers, которые при 
  запуске тестов поднимают реальный контейнер PostgreSQL в Docker.


5. Модуль «Competing Consumers / Work Queues» (Spring Boot + RabbitMQ)
--------------------------------------------------------------------------------
Проблема: При высокой нагрузке один консьюмер не успевает обрабатывать входящий 
поток тяжелых задач, из-за чего очередь критически растет.
Что пишем:
- Масштабирование консьюмеров с настройкой параллельных потоков (concurrent 
  consumers) и корректным prefetchCount.
- Сериализация сообщений в JSON через Jackson2JsonMessageConverter.
- Балансировка задач между параллельными воркерами с обработкой подтверждений 
  (ACK/NACK).


6. Модуль «Saga Pattern / Orchestration» (Spring Boot + Camunda / Custom State Machine)
--------------------------------------------------------------------------------
Проблема: В распределенных сервисах нельзя использовать классический ACID 
@Transactional для распределенных транзакций между разными БД.
Что пишем:
- Реализация Saga Orchestrator для распределенных бизнес-процессов (например, 
  заказ -> оплата -> доставка).
- Механизм компенсации (Compensating Transactions) для отката выполненных 
  шагов в случае ошибки на одном из этапов.


7. Модуль «CQRS & Read Database Synchronization» (Spring Boot + PostgreSQL + Elasticsearch/Mongo + Kafka)
--------------------------------------------------------------------------------
Проблема: Сложные аналитические и поисковые SQL-запросы замедляют реляционную 
БД, предназначенную для быстрого OLTP-записи.
Что пишем:
- Разделение модели записи (Command - PostgreSQL) и модели чтения (Query - 
  Elasticsearch/MongoDB/Redis).
- Настройка асинхронной синхронизации Read-модели через события в Kafka для 
  быстрого полнотекстового поиска и оптимизированных чтений.
